### PART 2: REAL-TIME DATA PERSISTENCE & STATE MANAGEMENT

This is the most critical technical requirement. Currently, data is saved to JSON files and loaded into `st.session_state` on first access. This works for local users but has issues:

**2.1 — Bulletproof data persistence**
- Currently `utils/data_persistence.py` is 26 lines of basic JSON read/write. Enhance it:
  - Add file locking to prevent corruption if two browser tabs write simultaneously (use `fcntl` on Unix or `msvcrt` on Windows, or a cross-platform library)
  - Add automatic backup: before every save, copy the current file to `data/backups/{filename}.{timestamp}.json` (keep last 5 backups per file, auto-cleanup older ones)
  - Add error recovery: if a JSON file is corrupted (JSONDecodeError), try to restore from the most recent backup automatically
  - Add a `save_json` wrapper that validates the data structure before writing (e.g., goals.json should always have a "goals" key that's a list)

**2.2 — Session state synchronization**
- Currently, each module loads data into session_state ONCE on first render, then works from memory. If the user has two tabs open, changes in one tab are invisible to the other. Fix this by:
  - Adding a `_needs_reload(filename)` check that compares the file's mtime to a stored timestamp in session_state — if the file changed on disk, reload it
  - Every module's `render()` should call this check at the top
- Make sure ALL save operations update BOTH session_state AND disk atomically — currently some modules update session_state first and save later, which can lead to state drift

**2.3 — Data survives across sessions**
- Verify that ALL 7 data files are correctly saved and loaded:
  - `receipts.json` — array of receipt objects
  - `portfolio.json` — object with holdings, alerts, watchlist arrays
  - `transactions.json` — array of transaction records (Report Generator)
  - `statement_transactions.json` — array of statement records (Subscription Auditor)
  - `budgets.json` — object with "budgets" dict
  - `goals.json` — object with "goals" array (each goal has history array)
  - `job_applications.json` — object with "clients" and "invoices" arrays (Freelance Dashboard)
- The Budget Tracker stores analyzed transactions in `st.session_state.budget_transactions` but does NOT persist them to disk — if the user closes the browser, the categorized transactions are lost. Fix this by saving them in budgets.json alongside the budgets dict
- The Subscription Auditor has the same issue with `st.session_state.sub_decisions` (Keep/Cancel toggles) — persist these to a file

**2.4 — Real-time UI updates**
- After every save/import action, the UI should immediately reflect the change without requiring a manual page refresh
- Replace remaining `st.success()` calls with `st.toast()` for non-blocking notifications (some modules still use st.success)
- Add `st.spinner()` wrappers around ALL data processing, API calls, and file operations that take > 0.5 seconds
- The dashboard in app.py loads data directly from JSON files every render — this is correct for real-time updates, keep this pattern
